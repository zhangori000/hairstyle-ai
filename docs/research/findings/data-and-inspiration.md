# Test data, taxonomy, evaluation and design inspiration

_Research lane `data-and-inspiration` from the 2026-10-20 sweep. Written by a research agent, then fact-checked by independent verifier agents; the verification section at the end records every correction. Numbers carry an as-of date and a source. Items marked unverified could not be confirmed from this sandbox (many vendor sites were blocked) and should be re-checked on the live page before you rely on them._

Long-form notes with every URL: [notes/data-and-inspiration.md](../notes/data-and-inspiration.md)

## Summary

Caveat: the shared WebSearch budget was exhausted before this lane ran, so all evidence comes from direct reads of primary sources reachable from the sandbox (github.com, raw.githubusercontent.com, api.github.com), GitHub connector search, and Mobbin; arXiv, Hugging Face, Kaggle, Wikipedia, Unsplash/Pexels and skintone.google were unreachable and items from memory are flagged.

Test data: nearly every real-face dataset is non-commercial research only (CelebA/CelebAMask-HQ, FFHQ bundle CC BY-NC-SA with per-image Flickr licenses and an explicit no-facial-recognition clause, Figaro-1k unstated, LaPa, HiSa, FaceSynthetics R-UDA which even taints "Results", DigiFace-1M). K-Hairstyle has no published license at all and its faces are blurred. The two permissive sources are SFHQ (~425k synthetic 1024px faces, MIT, with CLIP features and hairline landmarks for subject selection) and FairFace (CC BY 4.0, demographic coverage but tight low-res crops). Plan: consented friend photos as Tier 0 (with a consent manifest, gitignored), SFHQ synthetic subjects as the shippable CI golden set, research sets only for offline benchmarking.

Taxonomy: six open repos already hold structured catalogs; the best starting vocabulary is shape-up's 50-class list with synonyms (gender-inclusive, fades/tapers, protective styles), and the richest schema is headcutter's (synonyms, aiPrompt, maintenance, difficulty, contexts, norwoodMax, 0-1 compatibility scores for 9 face shapes, 12 textures 1A-4C, 3 densities). groomai shows barberScript + guardNumbers, the right stylist-handoff payload. LLMs generate names/schema reliably, but face-shape rules contradict across sources and trends are stale; keep them as soft, versioned, provenance-tagged priors.

Evaluation: use ArcFace/InsightFace buffalo_l (models non-commercial; keep in offline harness) with per-person calibrated floors rather than DeepFace's generic thresholds (ArcFace cosine-distance 0.68, Buffalo_L 0.55); masked LPIPS/DreamSim outside the hair mask; hair-mask IoU and Lab colour deltas via BiSeNet face parsing (hair label index differs between checkpoints: 17 in face-parsing.PyTorch vs 13 in CelebAMask-HQ's own script, verify empirically); CLIP only for coarse class checks because HairPairs shows CLIP ViT-B/16 reaches just AUC 0.80 / AP 0.16 on same-hairstyle verification; VIEScore-style VLM rubric (instruction-following 0-10, over-editing 0-10, naturalness 0-10, artifacts 0-10); no FID at friend-group scale. Friend protocol: blind A/B, 5 raters, three 1-5 questions, failure tags, bootstrap CIs and Bradley-Terry win rates.

Inspiration: ~70 Mobbin references captured and annotated (Noom lighting meter, MoonPay auto-capture, Warby Parker "erase your glasses" and no-face toast, Grok progressive blurred reveal, Zillow slider plus style rail plus thumbs, Krea resemblance knob, Linktree per-style thumbnails rendered on the user's own photo, Google Lens follow-up chips, Wise/Noom/Snapchat consent copy, Tinder on-device reassurance).

## Recommendations

- Build the test corpus in three tiers: Tier 0 consented friend photos (10-15 per person across lighting/pose/glasses/hat, gitignored, with a consent manifest and EXIF stripped), Tier 1 ~50 SFHQ synthetic subjects selected via its CLIP features to fill the coverage matrix (the only shippable CI set), Tier 2 research datasets (CelebAMask-HQ, Figaro-1k, HiSa, K-Hairstyle references) for offline benchmarking only.
- Freeze a 20-30 image golden set with hashes and store every render keyed by (model, prompt_version, image_id, seed) so provider or prompt changes are diffable.
- Seed the catalog from shape-up's 50 classes plus women's/textured additions from hair-ai, using headcutter's schema (synonyms, aiPrompt, stylistScript, maintenance weeks, styling minutes, grow-out, 1A-4C and density suitability, face-shape scores 0-1 with a confidence and provenance field); have an LLM draft it, a human review it, and validate with zod/pydantic in CI.
- Treat face-shape advice as soft priors shown as 'often suits', never as gates; refresh trend labels each season from Pinterest Predicts and Google Trends rather than from the LLM.
- Evaluation stack: identity via ArcFace cosine with per-person floors calibrated on real same-person pairs (not DeepFace's generic thresholds), masked LPIPS/DreamSim outside the dilated hair-mask union, hair-mask IoU and Lab colour delta via BiSeNet (verify hair index = 17 on your checkpoint), CLIP only for coarse class checks, VIEScore-style VLM rubric with four 0-10 sub-scores, no FID.
- Keep InsightFace models and all non-commercial datasets strictly inside the offline eval harness; never ship them in the app.
- Run a lightweight blind A/B friend study per model change: 5 raters, ~20 originals, three 1-5 questions ('still me', 'the style I asked for', 'would show a stylist') plus failure tags; report bootstrap CIs and Bradley-Terry win rates; automate a pre-gate (one face, identity floor, masked LPIPS, mask IoU band, VLM >= 6).
- Copy proven UI patterns: Noom-style lighting meter and MoonPay auto-capture during framing; Warby Parker 'erase your glasses' as 'hide current hair/hat'; Grok-style progressive reveal over the source photo while rendering; Zillow-style slider + style rail + thumbs on results; Linktree-style per-style thumbnails on the user's own face once cost allows; Google Lens-style refinement chips ('shorter', 'more curl', '5-minute version'); Wise/Noom/Snapchat-style consent with retention and delete-anytime; Unfold-style export sheet for the reference card plus stylist script.
- Use MediaPipe hair segmentation (Apache-2.0, on-device) for analysis and for any future live-video mode, so raw frames never leave the device unless the user explicitly sends a still to a cloud model.
- Before relying on them, verify the items this lane could not fetch: K-Hairstyle terms, Unsplash/Pexels model-release language, Monk scale license, ImagenHub/VIEScore combination formulas, and Kaggle hair-type/face-shape dataset provenance.

## Open questions

- What are K-Hairstyle's actual terms of use (HairPairs says none are published) and will the authors permit reference-image use in a hobby app?
- Is a commercially licensed face recognizer needed, or can identity scoring live only in the offline eval harness given InsightFace models are non-commercial?
- Do Unsplash/Pexels licenses (unreachable this run) permit using a stranger's face in try-on demos or screenshots, given no model-release guarantee?
- What are the exact overall-score formulas and GPT-4o vs human correlation numbers in the VIEScore and ImagenHub papers (tables were images or unreachable)?
- What retention period and third-party-API policy will the consent screen promise, and will face photos ever be sent to a cloud image model versus processed on device?
- Which hair label index does the chosen face-parsing checkpoint actually emit (17 vs 13), to be confirmed on one image before mask metrics are trusted?
- Are the Kaggle hair-type (5-class) and face-shape (5-class) datasets licensed and non-scraped enough to use even for local classifier experiments?
- Is the Monk Skin Tone scale license (believed CC BY 4.0) compatible with embedding it in the app's coverage schema?
- Does the owner have a stylist in the friend group who can review the LLM-drafted catalog's face-shape and maintenance fields?

## Findings (14)

- **[decision-critical]** _high confidence._ **Almost all real-face datasets usable for hair work are licensed for non-commercial research only; the only permissive options found are SFHQ (MIT, synthetic) and FairFace (CC BY 4.0).**  
  CelebAMask-HQ: 'RESTRICTED to non-commercial research and educational purposes', no redistribution. FFHQ: images under individual Flickr licenses (CC BY 2.0, CC BY-NC 2.0, PDM, CC0, US Gov), bundle CC BY-NC-SA 4.0, and 'should not be used for development or improvement of facial recognition technologies'. Microsoft FaceSynthetics: Research Use of Data Agreement v1.0, 'may not use the Data or any Results in any commercial offering'. LaPa, HiSa/HiDa, DigiFace-1M: non-commercial. SFHQ LICENSE file verified as MIT (Copyright 2022 David Beniaguev). FairFace README: CC BY 4.0.  
  Sources: <https://github.com/switchablenorms/CelebAMask-HQ>, <https://github.com/NVlabs/ffhq-dataset>, <https://raw.githubusercontent.com/microsoft/FaceSynthetics/main/LICENSE.txt>, <https://github.com/JDAI-CV/lapa-dataset>, <https://github.com/GAP-LAB-CUHK-SZ/HairStep>, <https://github.com/microsoft/DigiFace1M>, <https://raw.githubusercontent.com/SelfishGene/SFHQ-dataset/main/LICENSE>, <https://github.com/joojs/fairface>
- **[decision-critical]** _medium confidence._ **K-Hairstyle, the largest hairstyle dataset, has no published license or data-use agreement and its faces are de-identified, so it is only usable as hairstyle reference imagery and only after clarifying terms with the authors.**  
  HairPairs README (which builds on K-Hairstyle crops) states K-Hairstyle 'publishes no license or data-use agreement, so its image terms are unsettled' and that labellers saw hair crops only because faces are de-identified; its downloader pulls mq-train/mq-val (~22 GB). The official project page and paper were unreachable this run; size (~500k images, 31 classes) is from memory and not re-fetched.  
  Sources: <https://github.com/jhlimm8/HairPairs>, <https://arxiv.org/abs/2102.06288>
- **[decision-critical]** _high confidence._ **Off-the-shelf embeddings are weak hairstyle matchers, and attribute catalogs under-specify a hairstyle, so 'CLIP hairstyle match' should only be used for coarse class checks.**  
  HairPairs (ECCV 2026 workshop): 558 adjudicated pairs; crops sharing every K-Hairstyle cut-and-shape attribute were judged different hairstyles 98.8% of the time (410/415). Verification AUC/AP: CLIP ViT-B/16 0.804/0.156, SigLIP 0.733/0.074, DINOv2-B 0.715/0.062, DINOv2-L 0.671/0.085 (chance AP 0.018). In-domain training did not help.  
  Sources: <https://github.com/jhlimm8/HairPairs>
- **[decision-critical]** _high confidence._ **The hair label index in face-parsing masks differs between popular checkpoints (17 vs 13), so any mask-based hair metric must verify the index empirically per model.**  
  zllrunning/face-parsing.PyTorch prepropess_data.py enumerates atts from 1 with hair at 17 and hat 18; CelebAMask-HQ's own g_mask.py uses a different label_list order yielding hair = 13 and hat = 14 in saved PNGs.  
  Sources: <https://raw.githubusercontent.com/zllrunning/face-parsing.PyTorch/master/prepropess_data.py>, <https://raw.githubusercontent.com/switchablenorms/CelebAMask-HQ/master/face_parsing/Data_preprocessing/g_mask.py>
- **[decision-critical]** _high confidence._ **InsightFace pretrained recognition models (buffalo_l etc.) are non-commercial research only even though the library is MIT, so identity scoring must stay in an offline evaluation harness or use a separately licensed model.**  
  Model zoo: 'pretrained models are for non-commercial research purposes only, whether downloaded automatically or manually'; code MIT. buffalo_l = SCRFD-10GF + ResNet50@WebFace600K, 326 MB; accuracy MR-ALL 91.25, East Asian 74.96, LFW 99.83.  
  Sources: <https://raw.githubusercontent.com/deepinsight/insightface/master/python-package/docs/model_zoo.md>, <https://github.com/deepinsight/insightface>
- _high confidence._ **Generic face-verification thresholds exist but need per-person recalibration because a legitimate hairstyle change itself lowers ArcFace similarity.**  
  DeepFace config thresholds (cosine distance = 1 - cosine similarity): ArcFace 0.68, Buffalo_L 0.55, Facenet512 0.30, SFace 0.593, GhostFaceNet 0.65, VGG-Face 0.68. Recommended: measure sim between two real photos of the same friend with different hair/hat to set a per-person floor and report relative drop.  
  Sources: <https://raw.githubusercontent.com/serengil/deepface/master/deepface/config/threshold.py>, <https://raw.githubusercontent.com/serengil/deepface/master/deepface/modules/verification.py>
- _high confidence._ **Published hair-editing papers evaluate with FID/FID_CLIP + LPIPS/PSNR + identity + user studies; FID is unusable at friend-group scale.**  
  HairFastGAN's scripts/fid_metric.py computes FID and FID_CLIP via torchmetrics FrechetInceptionDistance with a CLIP extractor; README claims <1 s on V100; Barbershop reports a >95% user-preference study. clean-fid benchmarks use 10k-50k images and shows resizing/JPEG choices alone shift FID by >6.  
  Sources: <https://github.com/AIRI-Institute/HairFastGAN/blob/main/scripts/fid_metric.py>, <https://github.com/AIRI-Institute/HairFastGAN>, <https://github.com/ZPdesu/Barbershop>, <https://github.com/GaParmar/clean-fid>
- _high confidence._ **A ready-made VLM-as-judge rubric exists (VIEScore, MIT) with four 0-10 sub-scores that map directly onto hairstyle edits.**  
  Editing SC prompt: score1 = instruction followed (0 none, 10 perfect), score2 = over-editing (0 completely different, 10 'minimal edited yet effective'); PQ prompt: naturalness (0 wrong distance/shadow/lighting) and artifacts (0 distortion/watermark/blurred faces/unusual body parts). README says GPT-4o is 'on par correlation with human across all tasks' (numbers in an image table). ImagenHub (MIT) defines human SC/PQ; its {0,0.5,1} scale and sqrt(SC*PQ) overall are from memory, not re-fetched.  
  Sources: <https://github.com/TIGER-AI-Lab/VIEScore/blob/main/viescore/vie_prompts.py>, <https://github.com/TIGER-AI-Lab/VIEScore>, <https://github.com/TIGER-AI-Lab/ImagenHub>
- _high confidence._ **Open repos already contain structured hairstyle catalogs with the attributes the app needs; the shape-up 50-class list is the best gender-inclusive starting vocabulary and headcutter/groomai show the richest schemas.**  
  shape-up: 50 classes with synonyms and 12 CLIP prompt templates (buzz through knotless braids, low/mid/high taper, low/mid/high/skin/burst/drop/temple fade, bob/lob/pixie/bixie/shag/wolf/butterfly, afro/twist-out/bantu/locs/cornrows). headcutter haircuts.json: 25 fields incl. synonyms, aiPrompt, maintenance, difficulty, norwoodMax, faceCompatibility (9 shapes), textureCompatibility (1A-4C), densityCompatibility. groomai: barberScript, guardNumbers, maintenanceFrequency, front/side/back views. hair-ai: 44 Men/Women/Unisex styles with faceShapes, maintenance, stylingTime. AI_Trichologist: 197 canonical names from 11 scraped sites via deterministic mapping + LLM fallback with per-entry classification_source, 'Not licensed for commercial use'.  
  Sources: <https://github.com/brubru6707/shape-up/blob/main/haircut-classifier/taxonomy/prompts.json>, <https://github.com/LDAKrauser/headcutter/blob/main/scripts/output/haircuts.json>, <https://github.com/shabihhaider/groomai/blob/main/groomai/constants/hairstyles.ts>, <https://github.com/bhuvanmokati206-pixel/hair-ai-/blob/main/lib/hairstyleData.ts>, <https://github.com/akashkalamulla/AI_Trichologist>, <https://github.com/rlirli/hairhairhair/blob/main/src/content/hairstyles/hairstyle-edgar-cut.json>
- _high confidence._ **Face-shape-to-hairstyle rules are folk heuristics that contradict across sources, so an LLM-generated catalog must store them as soft priors with provenance, not facts.**  
  Findmycut face-shapes.json lists buzz cut under 'avoid' for round faces; hair-ai hairstyleData.ts lists Buzz Cut as suitable for Round. AI_Trichologist reports no evaluation of its LLM fallback classification. Names, synonyms and schema are consistent across repos; trends are time-sensitive.  
  Sources: <https://github.com/irsyaadbp/OpenClaw2026_Pencari-Kerja_Findmycut/blob/main/agent/src/knowledge/face-shapes.json>, <https://github.com/bhuvanmokati206-pixel/hair-ai-/blob/main/lib/hairstyleData.ts>, <https://github.com/akashkalamulla/AI_Trichologist>
- _high confidence._ **SFHQ is the best privacy-safe synthetic test-subject source but only covers FFHQ-aligned frontal faces, so in-the-wild selfie robustness still needs consented friend photos (or EasyPortrait, which lacks hair labels).**  
  SFHQ: ~425k 1024px images in 4 Kaggle parts, 110 landmarks incl. hairlines, BiSeNet segmentation, CLIP features for text search; author notes no occlusions except hair, no hats/earphones/jewelry, inherited biases. EasyPortrait v2: ~40k FullHD selfie portraits, 13,705 persons, CC BY-SA 4.0 variant, classes exclude hair. FaceSynthetics (non-commercial) has hair/beard/glasses/headwear/facewear labels for segmentation edge cases.  
  Sources: <https://github.com/SelfishGene/SFHQ-dataset>, <https://github.com/hukenovs/easyportrait>, <https://github.com/microsoft/FaceSynthetics>
- _medium confidence._ **On-device hair segmentation is available with a permissive license (MediaPipe hair_segmentation.tflite, Apache-2.0 code) for mask-based metrics and a future live-video mode.**

## Resources (46)

- **SFHQ synthetic faces (MIT)** (dataset) — <https://github.com/SelfishGene/SFHQ-dataset> — Only large, permissively licensed face source found; CLIP features let you pull subjects by hair texture, colour, skin tone, glasses, beard for the golden test set.
- **FFHQ dataset README and per-image license metadata** (dataset) — <https://github.com/NVlabs/ffhq-dataset> — De-facto aligned input format for all hair-editing models; JSON lets you filter CC0/PDM images; documents the no-facial-recognition restriction.
- **CelebAMask-HQ** (dataset) — <https://github.com/switchablenorms/CelebAMask-HQ> — Hair/hat/glasses masks for benchmarking segmentation and mask-based metrics (research only).
- **Microsoft FaceSynthetics** (dataset) — <https://github.com/microsoft/FaceSynthetics> — Synthetic faces with hair, beard, glasses, headwear, facewear labels for edge-case testing in dev (non-commercial).
- **HairPairs** (paper+dataset) — <https://github.com/jhlimm8/HairPairs> — Evidence on how weak CLIP/DINO are at hairstyle identity and a reusable verification protocol; also documents K-Hairstyle's unsettled license.
- **Figaro-1k via HairAnalysis** (dataset) — <https://github.com/UmarSpa/HairAnalysis> — Small texture-labelled hair-mask set (straight/wavy/curly/kinky/braids/dreadlocks/short) with a Dropbox link.
- **FairFace** (dataset) — <https://github.com/joojs/fairface> — CC BY 4.0 demographic coverage set for bias checks of detection/analysis.
