# Stretch features: reference-hair transfer and live video

_Research lane `reference-and-video` from the 2026-10-20 sweep. Written by a research agent, then fact-checked by independent verifier agents; the verification section at the end records every correction. Numbers carry an as-of date and a source. Items marked unverified could not be confirmed from this sandbox (many vendor sites were blocked) and should be re-checked on the live page before you rely on them._

Long-form notes with every URL: [notes/reference-and-video.md](../notes/reference-and-video.md)

## Summary

Method caveat: the shared WebSearch budget was exhausted before this lane ran and most vendor hosts (ai.google.dev, fal.ai, arxiv, HF, Snap, Banuba, DeepAR, Runway, Luma, Perfect Corp) did not resolve from the sandbox, so evidence comes from GitHub primary sources (official cookbooks, SDK docstrings, repos, a harvested Perfect Corp OpenAPI spec) plus the LiteLLM price table (secondary, fetched 2026-10-20). Memory-only claims are flagged in the notes.

Tier 1 (still photo, reference hair -> user): feasible now and cheap. Gemini Nano Banana 2/2.1/Pro take up to 14 input images (3 on Lite, 6 in high-fidelity mode) at $0.034-0.134/image; gpt-image edits take up to 16 images with input_fidelity=high on gpt-image-1/1.5 (gpt-image-2 ~$0.05 medium, ~$0.006 low). Perfect Corp sells a dedicated reference endpoint (/s2s/v2.1/task/hair-transfer). Research code: HairFastGAN (<1 s, MIT, aligned crops only), Stable-Hair (Apache, SD1.5, long hair fails), HairPort (SIGGRAPH 2026, 3D-aware, best for pose gaps, CC BY-NC-ND, minutes/pair, >=24 GB VRAM). Documented failure modes: identity drift (Qwen-Image #88), long hair outside the crop (HairFastGAN #5, Stable-Hair #12), pose/scale gaps (Style-Your-Hair, HairPort), stacked edits degrading after 3-6 passes, curly/kinky under-representation, no reliable auto-metric (HairPairs). Mitigations with evidence: bald-first, describe-then-generate (structured HairSpec), mask-only edits, N candidates + identity/VLM ranking, re-edit from the original, previous_interaction_id for refinement.

Tier 2 (multi-angle stills): feasible but inconsistent; best when the user supplies front/side/back photos (Google's hairstyle-ai-studio sample does this).

Tier 3 (turntable clip): feasible and far cheaper than per-frame editing ($4-5 for 120 frames vs $0.30-1.60 per 5-6 s via Veo 3.1 Lite/Fast, Hailuo 3, Wan 2.7, Seedance 2.0; self-hosted LivePortrait ~15 ms/frame on a 4090 but InsightFace non-commercial). Veo 3.1 takes up to 3 reference images; Gemini Omni Flash 1.1 can edit uploaded real video (<=10 s, not in EEA/UK/CH) - untested for hair.

Tier 4 (live camera): no photoreal generative new cut exists in 2026. Live means recolor via hair segmentation (MediaPipe hair_segmenter in-browser, on-device; Banuba gradient/strands) or 3D hair-asset overlays (Snap Lens Studio Head Binding + Head Occluder + Hair Simulation via free-with-approval Camera Kit; Unity AR Foundation). Reference->3D strands (DiffLocks, Im2Haircut) takes minutes on an A100 under non-commercial licenses and still looks CG. Meta Spark is dead; ModiFace is not self-serve.

Recommendation: ship Tier 1 + Tier 3; offer live only as recolor + fun overlays, labeled as such.

## Recommendations

- Build the reference-hair feature as a still-photo pipeline: VLM converts the reference into a structured HairSpec (length, parting, fringe, layers, texture, volume, colour/roots, finish, beard), then send [user photo, reference photo, HairSpec] to a multi-image editor (Nano Banana 2/2.1 for cheap candidates, Nano Banana Pro or gpt-image-1.5 input_fidelity=high for the hero), generating 3-4 candidates per look (~$0.15-0.60).
- Auto-rank and filter candidates: ArcFace identity similarity to the original (reject drift), hair-region change magnitude (reject no-ops), VLM judge against the HairSpec; always re-edit from the original photo plus an updated spec rather than chaining edits (stacked edits degrade after 3-6 passes).
- Split colour from cut: run cut first, colour as a second explicit field/pass; keep beard as its own field.
- Ask for head-and-shoulders photos (not tight face crops) and, optionally, front + 3/4 + side; for multi-angle output edit each user photo with the same HairSpec instead of asking a model to rotate the head.
- For the 'video' stretch, ship a 4-8 s turntable generated from the chosen still via image-to-video (Veo 3.1 Lite/Fast, Hailuo 3, Wan 2.7; $0.30-0.60) and pass the user's side photo as a second reference where the API allows; prototype Gemini Omni Flash 1.1 editing of an uploaded 8 s selfie video as an experiment, not a promise.
- For live camera, scope to (a) on-device hair recolor using MediaPipe hair_segmenter in the browser or app (fully private) and (b) optional 3D hair-asset lenses via Snap Camera Kit/Lens Studio (Head Binding + Head Occluder + Hair Simulation) if Snap approval and online-only are acceptable; label it as 'preview', not photoreal.
- Do not plan a product on HairPort/Stable-Hair/Im2Haircut/DiffLocks code paths (non-commercial licences, A100-minutes per job); use them only for internal quality benchmarks or to borrow ideas (bald-first, 3D pose alignment).
- If a vendor API is preferred for reference transfer, evaluate Perfect Corp's /s2s/v2.1/task/hair-transfer against Nano Banana on the same 20-30 image consented eval set before paying for credits; get its per-feature credit cost from GET /s2s/v2.0/credit/feature-cost.
- Adopt the hairstyle-ai-studio privacy pattern: downscale on device, server-side key proxy with rate limits, local-only history (IndexedDB/app sandbox), no server retention of faces; keep the live recolor path entirely on-device.
- Re-verify prices and limits on the official pages (ai.google.dev pricing, OpenAI pricing, Perfect Corp, Snap Camera Kit terms, fal model pages) before budgeting; this lane could only reach GitHub-hosted sources and the LiteLLM table.

## Findings (18)

- **[decision-critical]** _high confidence._ **Gemini Nano Banana models accept many reference images (up to 14 on gemini-3.1-flash-image and gemini-3-pro-image-preview, 6 in high-fidelity mode, 3 on the Lite model) and support 512px/1K/2K/4K output plus previous_interaction_id for consistent iterative edits.**  
  Verified in Google's official cookbook notebook (fetched 2026-10-20). Four models: gemini-3.1-flash-lite-image (free tier), gemini-3.1-flash-image (NB2), gemini-nano-banana-2.1, gemini-3-pro-image-preview (NB Pro, thinking, 4K). This is the simplest hosted path for 'put the hair from image 2 on the person in image 1' and for the refine loop.  
  Sources: <https://github.com/google-gemini/cookbook/blob/main/quickstarts/Get_Started_Nano_Banana.ipynb>
- **[decision-critical]** _high confidence._ **OpenAI images.edit accepts up to 16 input images; input_fidelity=high (facial-feature preservation) exists only on gpt-image-1 and gpt-image-1.5, and must be omitted for gpt-image-2 / 2.5; a mask applies to the first image only.**  
  From the openai-python SDK docstring. Models listed: gpt-image-1, -1-mini, -1.5, gpt-image-2 (2026-04-21), gpt-image-2.5-sunburst/-flare (2026-09-08), chatgpt-image-latest. gpt-image-2 family allows custom sizes up to 3840x2160.  
  Sources: <https://github.com/openai/openai-python/blob/main/src/openai/resources/images.py>, <https://github.com/DeanOpen/barber-ai>
- _high confidence._ **Perfect Corp's YouCam AI API has a dedicated reference-based hairstyle transfer endpoint (POST /s2s/v2.0/task/hair-transfer and /s2s/v2.1/task/hair-transfer taking a source photo plus a reference photo or template), alongside hair-color, hair-ext, hair-vol, hair-bang, wavy-hair and hair-type/length/density/frizziness detection; it is async, credit-based, and has a feature-cost endpoint.**  
  Spec harvested from docs.perfectcorp.com on 2026-09-02 by api-evangelist (third-party mirror of the vendor contract). USD credit pricing could not be fetched this session.  
  Sources: <https://github.com/api-evangelist/perfect-corp>, <https://raw.githubusercontent.com/api-evangelist/perfect-corp/main/openapi/perfect-corp-s2s-api-openapi.yml>
- **[decision-critical]** _high confidence._ **HairPort (SIGGRAPH 2026) is the current state of the art for reference hair transfer under large pose/scale differences, but it is CC BY-NC-ND 4.0, needs >=24 GB VRAM + Blender, takes 'several minutes per transfer pair', and depends on non-commercial FLUX.1-Kontext-dev, AGPL YOLOv8 and MPI-licensed FLAME/SMPL-X.**  
  Pipeline: LoRA Bald Converter on FLUX Kontext-dev trained on the new 6,400-pair Baldy dataset; Hi3DGen mesh + MV-Adapter texturing + Blender re-render of the reference hair from the user's viewpoint; Poisson blend; flow-matching synthesis. Reusable assets: Bald Converter LoRA and Baldy dataset on HF (check licence).  
  Sources: <https://github.com/deepmancer/HairPort>, <https://huggingface.co/deepmancer/bald_konverter>, <https://huggingface.co/datasets/deepmancer/baldy>
- _high confidence._ **Open research hair-transfer code has documented, specific failure modes: HairFastGAN and Stable-Hair fail on long hair outside the FFHQ-style crop; Stable-Hair results on new identities look stiff and depend on its bald-conversion stage; Barbershop does not transfer facial hair; pose-aligned inputs are assumed by most methods.**  
  Evidence: HairFastGAN issue #5 ('Training for long hairs'), Stable-Hair issues #12 (long female hair) and #14 (other IDs poor fit), Stable-Hair README (depends on Stage 1 bald converter, trained on ~6k/20k images), Barbershop issue #51, Style-Your-Hair and HairPort abstracts on pose gaps. HairFastGAN runs <1 s on a V100 (MIT); Stable-Hair is Apache-2.0 on SD1.5.  
  Sources: <https://github.com/AIRI-Institute/HairFastGAN/issues/5>, <https://github.com/Xiaojiu-z/Stable-Hair/issues/12>, <https://github.com/Xiaojiu-z/Stable-Hair/issues/14>, <https://github.com/Xiaojiu-z/Stable-Hair>, <https://github.com/ZPdesu/Barbershop/issues/51>, <https://github.com/Taeu/Style-Your-Hair>
- **[decision-critical]** _high confidence._ **Identity drift is the default failure of general image editors: Qwen-Image-Edit changed the face when only background/clothes were requested (issue #88, still open), stacked edits degrade after 3-6 passes, and OmniGen2's own README recommends generating several candidates and raising image_guidance_scale because subjects drift.**  
  Implication for the app: never chain edits on outputs; re-edit from the original photo with an updated spec, generate N candidates, and auto-reject with a face-identity check. Prompt libraries for Nano Banana / GPT Image are dominated by 'keep face 100% identical' boilerplate for the same reason.  
  Sources: <https://github.com/QwenLM/Qwen-Image/issues/88>, <https://github.com/VectorSpaceLab/OmniGen2>, <https://github.com/YouMind-OpenLab/awesome-nano-banana-pro-prompts>
- _medium confidence._ **There is no reliable automatic metric for 'did we reproduce the reference hairstyle': HairPairs shows CLIP ViT-B/16 reaches only ROC-AUC 0.80 at same/different hairstyle verification and 98.8% of pairs sharing every K-Hairstyle cut/shape attribute are still judged different hairstyles by humans.**  
  So auto-ranking should combine an identity-preservation score (ArcFace vs original), a hair-region-changed score, and a VLM judge against a structured HairSpec, then let the user pick.  
  Sources: <https://github.com/jhlimm8/HairPairs>, <https://github.com/AIRI-Institute/HairFastGAN>
- _high confidence._ **Public hairstyle apps already use the describe-then-generate and multi-view-photo patterns: Google's hairstyle-ai-studio sample asks for front/side/back photos, uses gemini-3.1-flash-lite-image, exports a stylist brief, downscales client-side, proxies the key server-side and keeps history in IndexedDB; XZL's app runs gemini-2.5-pro analysis then gemini-2.5-flash-image 'Hairstyle Fusion' from a reference photo.**  
  These are directly reusable architectural templates for privacy and for the 'reference image' feature.  
  Sources: <https://github.com/ryanbaumann/hairstyle-ai-studio>, <https://github.com/XZL-CODE/AI-Hair-Stylist-and-Advisor>, <https://github.com/ch-neural/AI-Hair-Salon>
