# Architecture and engineering practices for an AI-heavy app

_Research lane `architecture` from the 2026-10-20 sweep. Written by a research agent, then fact-checked by independent verifier agents; the verification section at the end records every correction. Numbers carry an as-of date and a source. Items marked unverified could not be confirmed from this sandbox (many vendor sites were blocked) and should be re-checked on the live page before you rely on them._

Long-form notes with every URL: [notes/architecture.md](../notes/architecture.md)

## Summary

Evidence base: primary docs/repos only (WebSearch budget was exhausted before this lane ran; many vendor hosts were blocked by the proxy, so docs were read from their public GitHub source, code.claude.com, developer.apple.com and the Vercel docs tool; unverifiable claims are flagged). Recommended MVP shape for a friends-only, AI-heavy app built with AI assistants: (1) Next.js PWA on Vercel/Cloudflare; camera via `<input capture="user">` first, getUserMedia second; no native app until live-video try-on is the core feature (TestFlight: 100 internal/10,000 external testers, 90-day build expiry; ad hoc: 100 iPhones/yr with UDIDs). (2) Client flow state as ONE discriminated-union Session type + pure exhaustive reducer (React docs and Effective TypeScript Item 29 both say replace boolean flags with a status union); promote to XState v5 (5.33.3) only if parallel regions/hierarchical sub-flows appear; XState v6 and Stately Agent are alpha, do not adopt. (3) Long-running generation: a jobs table + one durable-execution runner (Vercel Workflow DevKit 'use workflow'/'use step' with defineHook for the refine loop, still beta; or Trigger.dev/Inngest, both with Realtime hooks for progress). Event bus/CQRS/event sourcing/Temporal are not warranted. (4) Typing: TS strict + ts-reset + t3-env + Zod 4 (4.6.7; 1.88kb mini, JSON Schema, codecs, Standard Schema) at every boundary, branded IDs, exhaustive switches; AI outputs via AI SDK 7 `Output.object` (no built-in repair; NoObjectGeneratedError). (5) "Zero comments" should mean no comments that restate code/types, but keep why/invariant comments and the privacy comments CLAUDE.md already mandates; put navigation knowledge in a short CLAUDE.md, ADRs, path-scoped rules and tests-as-spec (Anthropic: prune CLAUDE.md, hooks are deterministic, verification + adversarial review). (6) Observability via @ai-sdk/otel (GenAI semconv, still Development status) to Langfuse (MIT, self-host) or Helicone (10k req/mo free) with recordInputs:false. (7) Privacy: client resize+EXIF strip via createImageBitmap/OffscreenCanvas (Safari 16.4+), direct-to-private-bucket upload, R2 lifecycle expiry ($0.015/GB-mo, free egress) or Supabase signed URLs (cannot be revoked early), AI Gateway zeroDataRetention. (8) Spend: gateway budgets (min $1, HTTP 402), spend webhooks, per-user caps + kill switch. (9) Auth: better-auth magic link (5-min single-use, 5 req/60s) + allowlist; passkeys later.

## Recommendations

- DO NOW: Next.js App Router PWA + TypeScript strict (strict, noUncheckedIndexedAccess, exactOptionalPropertyTypes) + ts-reset + t3-env + Zod 4; eslint switch-exhaustiveness; branded ids for PhotoId/SessionId/JobId/SignedUrl.
- DO NOW: one `Session` discriminated union + pure `(state, event) => state` reducer with table tests; only promote to XState v5 (never v6 alpha) when parallel regions or hierarchical sub-flows show up; consider @xstate/store as the middle step.
- DO NOW: a `jobs` table (status, attempt, input/output JSON, error, cost) + one durable runner. On Vercel: Workflow DevKit (accept beta risk; use defineHook for the refine loop). If avoiding beta/lock-in: Trigger.dev (no max run duration, Realtime hooks) or Inngest (self-hostable). Progress via Realtime hooks, SSE route handler, or 2-second polling.
- DON'T YET: event bus, CQRS, event sourcing, message broker, Temporal, microservices, Effect-TS, Stately Agent, GraphQL/tRPC layers, custom observability stacks.
- DO NOW: typed AI outputs with AI SDK 7 `generateText({ output: Output.object({ schema }) })`; version each schema; persist raw model text; implement your own validate-and-retry loop since the SDK has no repair step; hide image providers behind createProviderRegistry/customProvider and a single internal `renderStyle(input)` interface because editing APIs differ per provider.
- DO NOW: client preprocessing: `<input type=file accept=image/* capture=user>` -> createImageBitmap (EXIF from-image) -> OffscreenCanvas -> JPEG ~1536-2048px q0.85 (strips EXIF); lazy-load heic-to as fallback; keep a server-side sharp fallback; upload direct-to-bucket with server-issued tokens.
- DO NOW: private bucket (R2 free tier with prefix lifecycle rule, or Supabase with minutes-long signed URLs and a cron delete) + a user-facing delete-everything action; never log image bytes or signed URLs; set AI telemetry recordInputs/recordOutputs=false; use AI Gateway zeroDataRetention/disallowPromptTraining where available.
- DO NOW: layered spend control: gateway/provider budget (402 on exceed), platform spend webhook, per-user daily render cap in DB, idempotency keys, global kill-switch env var; per-user rate limit via Upstash Ratelimit or @vercel/firewall checkRateLimit keyed by user id.
- DO NOW: better-auth magic link with disableSignUp + email allowlist or invite code; add passkeys once friends are onboarded.
- DO NOW: observability = @ai-sdk/otel -> Langfuse (self-host or cloud) or Helicone free tier; add a feedback table (thumbs + reason per render) from day one; build evals only after ~50 real sessions.
- DO NOW (repo conventions for AI assistants): CLAUDE.md under ~60 lines with only non-derivable rules; AGENTS.md alias; docs/decisions ADRs; docs/privacy.md data-flow table; .claude/rules for lib/privacy/**; hooks that run typecheck+lint after edits; /code-review subagent before PRs; small kebab-case files with colocated *.test.ts and *.test-d.ts; bug fixes require a failing-then-passing test; no AI footers in commits; comments only for why/invariants/privacy, never for restating code or types; no commented-out code.
- DO NOW: write the server job status transitions as a tiny guarded state table in one module (queued->running->succeeded|failed|cancelled) so client and server share the same vocabulary without an event system.
- REVISIT LATER: Expo/native only if live-video try-on becomes the core feature; keep the server API client-agnostic so an Expo shell could reuse it.

## Open questions

- Vercel Workflow DevKit is still beta (5.0.0-beta.x) and its pricing could not be read in this session: is beta risk acceptable, or should the runner be Trigger.dev/Inngest from day one?
- Which image-editing provider (Gemini image models via generateText files, FLUX Kontext/Fill, gpt-image-2 edits) best preserves identity for hair transfer? This determines whether the render job is one call or a segmentation+mask+inpaint pipeline, and thus the job schema (AI-provider lane).
- Does current iOS Safari decode HEIC in createImageBitmap, and does <input capture> deliver JPEG from the camera? Needs an on-device test; WebKit/Apple release notes were unreachable.
- Does getUserMedia work inside an installed (home-screen) PWA on current iOS? Historically added in iOS 13.4 but unverified this session; affects whether live preview is feasible on the web path.
- Is the deployment on Vercel Hobby (non-commercial terms, unverified this session) acceptable for a friends-only app, and what are current Vercel Blob prices and the request-body limit (4.5 MB from prior knowledge)?
- What default retention for face photos and renders (suggest 7 days, user-deletable), and should renders be stored at all or regenerated on demand?
- Langfuse Cloud free-tier numbers and Braintrust pricing could not be verified (hosts blocked); confirm before choosing between self-hosting Langfuse and a hosted free tier.
- Will friends actually install the PWA (manual Share -> Add to Home Screen on iOS) or use Safari tabs? Decides whether service worker/push work is worth doing in the MVP.
- Expo EAS pricing and current TestFlight/App Store Connect fee ($99/yr assumed) were not verifiable this session; only relevant if native is revisited.

## Findings (13)

- **[decision-critical]** _high confidence._ **Model the capture->analyze->suggest->render->refine flow as a discriminated-union state with a pure exhaustive reducer; use full XState only when parallel/hierarchical behaviour appears.**  
  React docs explicitly replace isSending/isSent booleans with one `status` variable and say reducers pay off when many handlers update state and are testable in isolation but 'You don't need reducers everywhere.' Effective TypeScript items 29/34/59/64 codify unions of interfaces, never-exhaustiveness and brands. Stately's own README: use @xstate/store for simple Redux/Zustand-like state, `xstate` for complex workflow logic; store can be converted to a machine later. XState v5 requires TS>=5, strictNullChecks, setup({types}) and assertEvent; typegen is gone.  
  Sources: <https://github.com/reactjs/react.dev/blob/main/src/content/learn/choosing-the-state-structure.md>, <https://github.com/reactjs/react.dev/blob/main/src/content/learn/extracting-state-logic-into-a-reducer.md>, <https://github.com/danvk/effective-typescript>, <https://github.com/statelyai/xstate>, <https://github.com/statelyai/docs/blob/main/content/docs/typescript.mdx>, <https://github.com/statelyai/xstate/blob/main/packages/xstate-store/README.md>
- **[decision-critical]** _high confidence._ **XState v6 and Stately Agent are alpha as of 2026-10-20; XState v5.33.3 is the stable line.**  
  xstate core on main is 5.33.3; the `next` branch is 6.0.0-alpha.70. @statelyai/agent 2 is alpha, requires xstate 6 alpha and Node>=22.18, and its docs say to pin an exact version. Its pattern ('the machine decides which work is legal; the host executes model calls') is worth copying by hand, not adopting as a dependency.  
  Sources: <https://raw.githubusercontent.com/statelyai/xstate/main/packages/core/package.json>, <https://raw.githubusercontent.com/statelyai/xstate/next/packages/core/package.json>, <https://github.com/statelyai/agent>, <https://github.com/statelyai/docs/blob/main/content/docs/agents/agents.mdx>
- **[decision-critical]** _high confidence._ **A jobs table plus one durable-execution runner is sufficient; event bus, CQRS, event sourcing and Temporal are not warranted at friends scale.**  
  Workload is 1-3 model calls per user action with one consumer. Vercel Workflow DevKit gives 'use workflow' (event-log replay), 'use step' retries, sleep without compute and defineHook pause/resume (fits the refine loop), local bundled backend and Postgres self-host, but is still beta (version 5.0.0-beta.33 referenced). Cloudflare Workflows: unlimited wall-clock per step, Free 1,024 steps/100 concurrent/100k runs/day, Paid 10,000 steps/30s CPU/30-day retention. Trigger.dev: no max run duration, Free concurrency 20, soft spend caps with 24h grace, Realtime hooks. Inngest: step.realtime.publish + useRealtime, self-hostable (SSPL). Temporal Cloud pricing is not in its docs repo.  
  Sources: <https://vercel.com/docs/workflows>, <https://github.com/vercel/workflow>, <https://github.com/cloudflare/cloudflare-docs/blob/production/src/content/docs/workflows/reference/limits.mdx>, <https://github.com/triggerdotdev/trigger.dev/blob/main/docs/limits.mdx>, <https://github.com/triggerdotdev/trigger.dev/blob/main/docs/billing-limits.mdx>, <https://github.com/inngest/website/blob/main/pages/docs/realtime/index.mdx>, <https://github.com/inngest/inngest>
- _high confidence._ **Use Zod 4 (or Valibot/zod-mini on the client) at every boundary; all three options plus t3-env, @xstate/store and AI SDK interoperate through Standard Schema.**  
  Zod 4.6.7: 14.71x faster string parsing vs Zod 3, core bundle 5.36kb gz (57% smaller), Zod Mini 1.88kb gz, ~100x fewer tsc instantiations, built-in z.toJSONSchema, codecs (base64ToBytes, isoDatetimeToDate) since 4.1, z.file().mime(), implements Standard Schema. Valibot starts under 700 bytes and claims up to 95% smaller bundles than Zod; @valibot/to-json-schema supports draft-07/2020-12/OpenAPI 3.0. ArkType's performance claims could not be verified (README has no numbers). t3-env accepts any Standard Schema validator and enforces NEXT_PUBLIC_ client split. ts-reset makes JSON.parse/.json() return unknown.
