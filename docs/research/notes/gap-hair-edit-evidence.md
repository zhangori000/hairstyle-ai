## 0. Headline answers (raw, see tables for sources)
- No independent, controlled hairstyle-vs-face-identity test exists for ANY of the Oct-2026 models (Nano Banana 2.1/Pro, GPT Image 2.5 Sunburst/Flare, FLUX 3 Image/Klein, Seedream 5.0 Pro, Qwen-Image 3.0/Edit 2511, Krea 3, Ideogram 4.5). All model-specific evidence is vendor docs, SEO blogs, or single-reviewer micro-tests. The only controlled academic evidence is on older models (FLUX.1 Dev / Kontext-Pro etc.): identity loss ~22-32% averaged across four edit types, and hair edits are the edit type that preserves identity BEST (pose worst) [S, arXiv 2608.28802].
- Chained edits: every source agrees drift accumulates across rounds. Informal 5-edit chain (thin method): FLUX Kontext barely drifts, Nano Banana drifts noticeably by edit 3, GPT-Image-1 by edit 2 [S, aiofm.info]. Nano Banana: "after about four back-and-forth edits faces softened and shifted; redo the hair change in a single step from the original" [S, aichangehair 2026]. Academic benchmark (arXiv 2609.04151, 2026): "subtle changes in facial characteristics accumulate across rounds"; GPT-IMAGE-2 appears in its drift-trajectory figure (numbers not captured) [S].
- Bald-first: mechanism is supported by research ablations (HairCLIPv2 ICCV 2023 supp: skipping the balding step leaves visible artifacts; skipping blending alters background/identity; HairNet ECCV 2022 uses baldification as stage 1) and every 2025-26 transfer pipeline (Stable-Hair, Stable-Hair v2, HairPort, DPF) is bald-then-inject [S/P]. Consumer-side only anecdote (Tom's Guide: Gemini struggles with updos unless you first make it bald) [PRIOR]. NO independent benchmark of bald-first vs direct for general editors. [U]
- Reference transfer ("hair from image 2 on person in image 1"): no systematic test found for any current model. Guides consistently warn hairline placement and texture vary with the source image; recommend front-facing photo with hair off the face, one attribute per pass (length -> texture -> colour), an explicit keep-list (face, jawline, skin tone, hairline), and naming which image controls which attribute. A vague "put the face from image 1 onto image 2" prompt let Nano Banana change the hairstyle entirely (kavel.ai face-swap test) [S]. H-Adapter's paper (PRIOR) says FLUX.2 tends to keep the SOURCE hairstyle and miss reference-specific attributes when poses differ.
- Latency: Seedream 5.0 Pro ~86-110 s/image [PRIOR]; FLUX 3 at 4K "can take several minutes" on fal [PRIOR]; H-Adapter 3.05 s per transfer [S, aggregator]; HairFastGAN 0.78 s V100 [PRIOR]; HairPort "several minutes per transfer pair" on >=24 GB GPU [P]. Nano Banana 2.1 / GPT Image 2.5 / Klein / Krea 3 / Ideogram 4.5 per-image latencies: not found this session [U].
- Real-time: Decart's public repos and pricing snippets show NO hair/haircut capability. Lucy 2.5 real-time video restyle $0.02/s at 720p (fast mode $0.04/s, US only), Lucy Restyle 2 $0.01/s at 720p, vendor latency claim "sub-40 ms" at 720p 30 fps; Lucy VTON (lucy-vton-3.6) is garments only, "accessories, bags, hats, jewelry may struggle"; Lucy Edit 1.1 Dev (5B, non-commercial weights) lists clothing/characters/objects/backgrounds, no hair examples, and "global transformations often change the identity of the subject" [S/P]. StreamDiffusion (orig) 93.9 fps img2img SD-turbo 1-step on RTX 4090 [P]; StreamDiffusionV2 (MLSys 2026 best paper, Apache-2.0, Wan2.1 1.3B/14B, 480x832 @ 16 fps setting) [P]; Daydream Scope hosts these pipelines [P]; none documents hair editing.

## 2. Reference-hair transfer: what works / where it fails (all sources)
- Workflow that guides converge on: upload both photos; say "hairstyle from Image 2 on the person in Image 1; do not change the face"; name which image controls which attribute; front-facing user photo with hair off the face; change length, then texture, then colour; keep the original on hand and restart from it. [S: media.io, insmind, seaart, glbgpt, nanobananaweb, kavel, xmk Seedream reference guide]
- Reported weak points: hairline placement and texture "can vary with the source image and model output"; facial consistency and lighting vary; identity drift after several edits. [S: media.io, nanobananaweb]
- Colour vs cut entanglement: no source isolates it for current models; HairFastGAN separates shape and colour references by design, which is the research answer. [PRIOR]
- Pose gap: H-Adapter (ECCV 2026) built specifically for pose-different pairs and reports FLUX.2 keeps the source hairstyle in that case [PRIOR]; HairPort built 3D re-rendering for "large viewpoint and scale differences, where missing hair has to be generated rather than copied" [P README]. Style-Your-Hair/HairFastGAN: large pose gap -> severe hair shifts [PRIOR].
- Textured / long hair: HairFastGAN cannot transfer ponytails, ribbons, braids; long->short leaves skin/shadow artifacts [PRIOR]; curly/kinky under-represented in training data (Perm README) [PRIOR]; Krea 2 note on extravagant hairstyles drifting to prior [S]. No 2026 model-specific evidence.
- Reference face leaking into the user: addressed only by prompt phrasing in apps [PRIOR]; kavel test shows the opposite failure (hair leaking) on vague prompts [S].

## 5. Ranked recommendation for this app (evidence-weighted)
1. Nano Banana 2.1 as default, Nano Banana Pro for the hero/export render — most hair-specific hands-on evidence, small facial shifts tolerable, drift manageable by always re-editing from the original. Confidence: medium (evidence is blogs, no controlled test).
2. FLUX 3 Image (hosted via marketplace) / FLUX 3 Image Klein (self-hosted) for the mask/box-locked "hair only" pass and as the privacy-first path — best pixel preservation outside the edit region in the only micro-benchmark; expect under-editing on reference transfer with pose gaps. Confidence: medium-low (single reviewer; FLUX.1-era academic data only).
3. GPT Image 2.5 Sunburst as A/B and for complex instructions — top of preference boards, official hairstyle template, but highest risk of whole-face re-rendering and no input_fidelity knob. Confidence: medium-low.
4. Seedream 5.0 Pro for the reference-hair experiment only — third-party identity-preserving-edit #1 claim, but ~90 s latency and no hair evidence. Confidence: low.
5. Qwen-Image-Edit-2511 self-hosted only with a per-user identity LoRA — hair edits are a documented face-recast case. Confidence: medium (failure well documented).
6. Krea 3 / Ideogram 4.5 — pixel-copy editors worth one bake-off slot; no evidence either way. Confidence: low.
7. Dedicated research models: HairFastGAN (<1 s, MIT code, NC StyleGAN weights) remains the only runnable reference-transfer specialist; HairPort/Stable-Hair v2 are minutes-per-pair or SD1.5-era research; H-Adapter and DPF have no code. Confidence: high for "no code" (GitHub searched), medium for quality claims.
8. Real-time: no vendor; ship recolor via on-device segmentation and still-image renders only. Confidence: high (Decart repos read directly).
Process rules supported by evidence: one attribute per pass; bald-first when target is shorter/tighter; never chain more than 1-2 edits from an output; always restart from the original; keep an explicit keep-list in the prompt; include the original as a reference in every pass; score ArcFace identity + outside-hair-mask SSIM in a 10-20 selfie x 10 style bake-off before locking a vendor.
