Research date (as_of for every number unless stated): 2026-10-20.
Method: ~55 WebSearch calls (standard + extended) plus direct fetches of GitHub repos/LICENSE files. Network limits in this sandbox: only github.com resolved for direct fetch; arxiv.org, huggingface.co, fal.ai, replicate.com, ai.google.dev, perfectcorp.com, docs.ultralytics.com did NOT resolve, so vendor pricing pages and paper PDFs were read through search-engine extracts (several independent extracts per number where possible). Important framing for this owner: the app is for a small group of friends (non-commercial). ### 1.2 Speed / hardware evidence
- HairFastGAN paper: color-only 0.52 s (V100) / 0.27 s (A100); shape-only 0.71 / 0.40 s; shape+color 0.78 s on V100. Independent benchmark in a later paper lists 0.78 s avg per pair. Requirements: Linux, NVIDIA GPU + CUDA, Python 3.10, PyTorch 1.13.1+. (https://arxiv.org/pdf/2404.01094 ; https://github.com/AIRI-Institute/HairFastGAN)
- Barbershop / Style-Your-Hair / LOHO: optimization-based → minutes per image (Replicate listing for style-your-hair shows T4 and a very long typical runtime). HairFastGAN's abstract calls optimization methods "inexcusably slow". (https://replicate.com/cjwbw/style-your-hair ; https://github.com/AIRI-Institute/HairFastGAN)
- Stable-Hair / v2: SD1.5-class; no VRAM figures published; v2 flagged as "more computationally intensive than GAN-based alternatives". (https://github.com/sunkymepro/StableHairV2 ; Lacuna review)
- HairPort: >=24 GB VRAM, Blender, several minutes per pair. (https://github.com/deepmancer/HairPort)
- All StyleGAN-family models (HairFastGAN, Barbershop, HairCLIP/v2, StyleYourHair, HairMapper) require FFHQ-style aligned 1024x1024 face crops. Output is the aligned crop, not the user's original framing: you must paste back (and the background/clothing outside the crop is lost or regenerated). This is a product-level constraint for "export a reference image".

### 1.3 Quality evidence (cross-paper, NOT directly comparable — protocols differ)
- Stable-Hair v2 single-view FID (lower better): Barbershop 46.1, HairCLIPv2 37.3, HairFastGAN 36.4, Stable-Hair 36.1, Stable-Hair v2 35.1. (https://arxiv.org/pdf/2507.07591)
- HairPort table: HairCLIPv2 38.5, HairFastGAN 37.1, Stable-Hair 64.9 FID; authors admit HairFastGAN has slightly lower FID than HairPort. (https://arxiv.org/html/2606.12562v2)
- HairFastGAN's own table: HairFastGAN 13.1 vs HairCLIPv2 14.3 vs Barbershop 15.9. (https://arxiv.org/pdf/2404.01094)
- H-Adapter pairwise user study on 200 CelebA-HQ triplets: H-Adapter preferred over HairCLIPv2 81.1%, over Stable-Hair 72.9%, over HairFastGAN only 55.3% (near coin-flip). (https://arxiv.org/pdf/2606.25578)
- Stable-Hair paper's qualitative claims: Barbershop "chaotic" on complex hairstyles; HairCLIP/v2 transfer the reference least faithfully. (https://arxiv.org/pdf/2407.14078)
- Takeaway: among runnable open models, HairFastGAN is still the best speed/quality/licence-clarity point for faithful reference transfer in 2026; diffusion successors (Stable-Hair, HairFusion) are not clearly better on FID and are heavier; the 2026 papers that beat it (H-Adapter, DPF) have no code; HairPort is a 9-stage research pipeline.

### 1.4 Documented failure modes (useful for test-case design)
- HairFastGAN: long→short hair leaves skin-texture/shadow artifacts; color transfer fails under large illumination differences; cannot transfer complex textures (ponytails, ribbons, braids); may leave hair when transferring "bald"; large pose gap between source and shape reference → severe hair shifts. (https://arxiv.org/pdf/2404.01094 ; https://liner.com/review/hairfastgan-realistic-and-robust-hair-transfer-with-a-fast-encoderbased)
- HairPort (on bald conversion generally): heavy occlusion, hats over hairline, extreme lighting/motion blur → hair remnants near boundaries or over-smoothed scalp. (https://arxiv.org/html/2606.12562v2)
- Stable-Hair: everything depends on stage-1 bald converter; small training set (6k/20k). (https://github.com/Xiaojiu-z/Stable-Hair)
- Stable-Hair v2: background reconstruction weakness → inter-frame flicker; attribute binding (colors to wrong subject). (https://pith.science/paper/2507.07591)
- General editors (see §4): updos/textured hair, identity drift after chained edits.

### 1.5 Bald-proxy pattern (a recurring design)
HairCLIPv2 (HairMapper proxy), Stable-Hair (Bald Converter), HairPort (LoRA on Kontext → `deepmancer/bald_konverter`, Baldy dataset 6,400 pairs), DPF (purifies the bald intermediate) all do "make bald first, then inject hair". Consumer evidence: Tom's Guide found Gemini struggles with updos "unless you first ask Gemini to edit you bald". For a general-editor pipeline, a two-step "bald → style" prompt chain is the cheapest way to get the same benefit. (https://github.com/deepmancer/HairPort ; https://github.com/Xiaojiu-z/Stable-Hair ; https://www.tomsguide.com/ai/google-gemini/i-used-googles-nano-banana-to-try-a-bunch-of-different-hairstyles-and-the-results-blew-me-away)

## 3. Segmentation and masks

### 3.1 MediaPipe Image Segmenter (Tasks API; Web via `@mediapipe/tasks-vision`)
- HairSegmenter: 512x512 float32, classes {0 background, 1 hair}; Pixel 6 avg latency 57.90 ms CPU / 52.14 ms GPU.
- SelfieMulticlass (256x256): classes {0 bg, 1 hair, 2 body-skin, 3 face-skin, 4 clothes, 5 others/accessories}; Pixel 6 217.76 ms CPU / 71.24 ms GPU (~16 MB per a Flutter wrapper).
- SelfieSegmenter 33–35 ms; DeepLab-V3 123.93 / 103.30 ms.
- Web: `ImageSegmenter` with `outputCategoryMask` (uint8 per-pixel winning class) and confidence masks; npm/CDN.
- Known bug: on iOS Safari with GPU delegate the multiclass category order came back scrambled (issue #6142, `@mediapipe/tasks-vision@0.10.22-rc.20250304`); desktop and iOS CPU fine → add a runtime sanity check for class indices.
- Quality: a Korean study says the hair model gives AR-grade masks but shows noise/holes for some hairstyles; per-frame predictions flicker on video (temporal smoothing needed).
- Legacy `hair_segmentation.tflite` at https://storage.googleapis.com/mediapipe-assets/hair_segmentation.tflite (legacy solutions support ended 2023-03-01). Model-card license not directly retrievable from this sandbox; third-party repackagers cite Apache-2.0 (verify at the model card).

### 3.4 Masks vs mattes

2. ### Where to combine
- On-device MediaPipe hair/multiclass mask (browser, ~50–70 ms) → (a) auto-crop to head region before anything leaves the device (privacy + less spill), (b) post-composite: copy original pixels back outside a feathered hair+forehead mask so skin/eyes/background are bit-exact after a general-editor edit, (c) hair-colour-only previews fully offline, (d) QA signal: compare hair mask area/shape before vs after to detect "nothing changed" or "face changed".
- Bald-first chain for general editors (mirrors Stable-Hair/HairPort pipelines and Tom's Guide's tip) when the target is shorter/tighter than the current hair (updo, buzz cut).
- HairFastGAN as the "exact copy of this photo's hair" engine and as a second opinion the user can vote on; general editor as the ideation/refine loop ("shorter", "more curl", "5-minute version").
- Hairmony taxonomy + HairCLIP style names → typed `HairDescription` produced by a VLM from the user's photo and from any reference photo; feed the same object to the prompt builder and to the stylist hand-off text.
- SAM 2 tiny / SAM 3 server-side to build ground-truth hair masks for your private test set (SAM 3 text prompt "hair" — verify vs point prompts).
